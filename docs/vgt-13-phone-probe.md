# VGT-13 휴대폰 보면대 연결 시험 (스파이크, 병합하지 않음)

이 시험은 Mac에서 곡이 재생되는 동안 휴대폰 화면에 지금 코드와 다음 코드를 크게 띄울 수 있는지, 그리고 코드가 바뀌는 순간이 Mac과 얼마나 어긋나는지를 실제 Wi-Fi에서 확인하기 위한 것입니다. 실제 곡 대신 90 BPM 합성 코드 진행을 쓰고, 소리와 가사는 전혀 보내지 않습니다.

구조는 2026-11-12에 고른 A안 그대로입니다.

- Mac의 확장 시험 페이지가 시각 정보(기준 시각, 재생 위치, 속도, 일시정지 여부)를 보냅니다. Mac이 시간의 기준입니다.
- `npm run phone`으로 띄우는 작은 중계 프로그램이 그 정보를 받아 같은 Wi-Fi의 휴대폰에 전달합니다. 클라우드를 거치지 않습니다.
- 휴대폰은 읽기만 하고, 받은 기준 시각에서 지금 위치를 스스로 계산합니다(위치 = 기준 위치 + 속도 × 지난 시간). 휴대폰과 Mac의 시계 차이는 ping 왕복으로 잽니다.
- 임시 목표는 "재생 중 코드가 바뀌는 순간의 차이 100 ms 이하"입니다.

## 실행 방법

1. 이 브랜치에서 `npm run build`를 실행합니다.
2. Chrome의 `chrome://extensions`에서 Vibe Guitar 확장을 **새로고침**합니다.
3. 확장 ID를 확인하고 Chrome 주소창에 `chrome-extension://<확장 ID>/phone-probe.html`을 엽니다.
4. 터미널에서 `npm run phone`을 실행합니다. 화면에 QR 코드와 `http://192.168.x.x:47822/?t=...` 주소가 나옵니다.
   - 처음 실행하면 macOS가 "node가 들어오는 연결을 허용할까요?"라고 물을 수 있습니다. **허용**을 눌러야 휴대폰이 접속할 수 있습니다. 거부했다면 시스템 설정 › 네트워크 › 방화벽 › 옵션에서 node를 허용으로 바꿉니다.
   - Wi-Fi 주소를 잘못 고르면 `npm run phone -- --host 192.168.x.x`로 직접 지정합니다.
5. 휴대폰을 **Mac과 같은 Wi-Fi**에 연결하고, 카메라로 QR 코드를 찍거나 주소를 직접 입력합니다.
6. 휴대폰의 **자동 잠금을 끕니다**. 이 페이지는 집 안 네트워크의 일반 http 주소라서 브라우저가 "화면 켜짐 유지" 기능을 허락하지 않습니다.
   - iPhone: 설정 › 디스플레이 및 밝기 › 자동 잠금 › 안 함
   - Android: 설정 › 디스플레이 › 화면 자동 꺼짐
   - 시험이 끝나면 원래대로 되돌려 주세요.
7. Mac의 시험 페이지에서 **재생**을 누릅니다. 끝낼 때는 터미널에서 Ctrl+C를 누릅니다. 중계 프로그램은 아무것도 저장하지 않으며, 다시 실행하면 토큰이 새로 바뀌므로 QR 코드도 다시 찍어야 합니다.

시험 페이지와 휴대폰 화면은 코드가 바뀔 때마다 화면 전체가 0.15초 동안 하얗게 번쩍입니다. 깜빡임에 민감하다면 오래 보지 마세요.

## 무엇을 볼까요

- **눈으로 보기**: Mac 화면과 휴대폰을 나란히 두고 번쩍이는 순간이 같아 보이는지 확인합니다.
- **슬로 모션 영상(가장 정확함)**: 다른 휴대폰이나 카메라의 슬로 모션(240fps 권장)으로 두 화면을 한 프레임에 함께 찍습니다. 두 번쩍임 사이의 프레임 수 × (1000 / 초당 프레임 수)가 실제 차이(ms)입니다. 240fps라면 1프레임이 약 4.2 ms입니다.
- **휴대폰 화면 아래의 작은 진단 줄**:
  - `offset ±`: 휴대폰 시계와 Mac 시계의 차이 추정값과 그 오차의 상한입니다. ping 한 번은 "실제 차이가 (그 표본의 추정값 ± 왕복 시간의 절반 + 시계 해상도 1 ms) 안에 있다"는 범위를 줍니다. 최근 표본 15개(약 30초)가 만드는 범위들이 겹치는 구간의 가운데를 추정값으로, 그 구간 폭의 절반을 `±`로 표시합니다. 그래서 왕복이 한쪽 방향만 느렸더라도 실제 차이는 `±` 안에 있습니다. 범위들이 겹치지 않으면 `(불일치)`가 붙고, 이때 `±`는 보장되지 않는 참고값입니다.
  - `RTT min`: 가장 빠른 왕복 시간
  - `change error`: 휴대폰이 코드를 바꾼 순간과 Mac이 바꾼 순간의 차이(휴대폰이 늦으면 양수). 이 값은 시계 추정을 거쳐서 계산하므로, 시계 추정 자체의 오차(`±` 값)는 보이지 않습니다. 그래서 영상 측정이 최종 기준입니다.
  - `reconnects`: 다시 연결된 횟수와 마지막으로 끊겨 있던 시간, `hidden`: 화면이 꺼지거나 다른 앱으로 넘어간 횟수
- 꼭 해 볼 조작: 재생/일시정지, 5초 앞뒤 이동, 속도 0.5배·0.75배·1배, 구간 반복 켜기와 "반복 시작점으로 이동", 그리고 재생 중에 Mac의 `npm run phone`을 Ctrl+C로 끄고 다시 켜기(휴대폰에 "다시 연결 중"이 떠야 합니다. 다시 켜면 토큰이 바뀌므로 QR 코드를 다시 찍어야 합니다), 휴대폰 Wi-Fi를 잠깐 껐다 켜기, Mac의 시험 페이지를 새로고침하기("Mac 확장 페이지가 꺼져 있어요"가 떴다가 저절로 돌아와야 합니다). 휴대폰은 6초 동안 아무 신호도 받지 못하면 연결을 버리고 다시 연결합니다.

## 보안을 위해 정한 것

- 확장 페이지가 접속하는 발행 주소(포트 47821)는 `127.0.0.1`에만 열립니다. 같은 Wi-Fi의 다른 기기는 접속할 수 없습니다. 또한 접속 요청의 `Origin`이 Chrome 확장(`chrome-extension://...`)이 아니면 거부하므로 일반 웹 페이지도 시각 정보를 보낼 수 없습니다. `--extension-id <ID>`를 주면 이 확장만 허용합니다.
- 휴대폰용 주소(포트 47822)는 Mac의 Wi-Fi 주소 하나에만 열립니다(0.0.0.0 금지).
- 실행할 때마다 128비트 무작위 토큰을 새로 만들어 QR 주소에 넣습니다. 토큰이 틀리면 페이지와 WebSocket 모두 거부합니다. 토큰은 메모리에만 있고 파일에 쓰지 않습니다.
- 이 토큰은 접근을 막는 장치일 뿐 암호화가 아닙니다. 연결은 일반 http이므로 **믿을 수 있는 집 Wi-Fi에서만** 쓰세요. 카페 같은 공용 Wi-Fi에서는 쓰지 마세요.
- `Host` 헤더가 광고한 주소와 다르면 거부합니다(DNS 리바인딩 방지). 휴대폰 WebSocket은 `Origin`도 같은 주소여야 합니다.
- 메시지는 8 KiB 이하만 받고, 형식을 엄격하게 검사한 뒤 검사를 통과한 값만 다시 만들어 보냅니다. 휴대폰은 ping 말고는 아무것도 보낼 수 없습니다. 초당 40개를 넘기거나 20초 동안 아무 신호가 없으면 연결을 끊습니다. 휴대폰은 최대 4대까지 접속할 수 있습니다.
- 휴대폰 페이지는 `Content-Security-Policy`로 같은 주소의 스크립트와 그 WebSocket 외에는 아무것도 불러오지 못하게 막습니다.
- 확장 manifest는 바꾸지 않았습니다. 확장 페이지의 CSP에 `connect-src` 제한이 없어서 `ws://127.0.0.1` 접속에 새 권한이 필요하지 않습니다. 빌드에는 `phone-probe` 페이지 하나만 추가했습니다.

## 개발자용 확인

- `npm run phone-check`: 중계 프로그램을 띄워 접근 규칙과 동작 26개 항목(잘못된 요청 뒤에도 계속 동작하는지 포함)을 확인하고, 가짜 발행자·가짜 휴대폰으로 왕복 시간과 코드 변경 시점 오차를 잰 뒤 종료합니다. 같은 Mac 안에서 재는 값이므로 실제 Wi-Fi 지연은 포함되지 않습니다.
- 순수 로직 테스트: `tests/phone-protocol.test.ts`, `tests/phone-ws-qr.test.ts`.
- QR 코드는 외부 패키지 없이 `src/phone/qr.ts`가 만듭니다(바이트 모드, 오류 정정 M, 버전 1–10). macOS CoreImage로 버전 1·4·8 예시를 해독해 원문과 일치하는 것을 확인했습니다.

## 화면 시안 (실제 기능용, 3종)

`docs/vgt-13-mockups/`에 있는 정적 HTML(스크립트 없음, 외부 요청 없음)과 PNG입니다. `node scripts/vgt13-mockups.mjs`로 다시 만들 수 있고, 코드 다이어그램은 사이드 패널과 같은 `renderShapeDiagram`으로 그립니다. 예시는 "원곡 A 키, 카포 2"이며, 한 화면에는 손 모양 이름 한 종류만 쓰고 "카포 2 모양"이라고 표시합니다(지금 G 모양, 3박 뒤 C 모양).

| 시안 | 특징 | 파일 |
| --- | --- | --- |
| A 무대형 | 한 줄로 쌓은 구성. 지금 코드 이름과 큰 다이어그램을 가운데에 두고, 아래에 마디 안 박자 칸과 "다음 C · 3박 뒤"를 둡니다. 어두운 화면과 밝은 화면을 같은 배치로 비교할 수 있습니다. | `a-stage-dark.html/.png`, `a-stage-light.html/.png` |
| B 악보대형 | 위아래 반으로 나눈 밝은 종이색 화면. 다음 코드까지 남은 박을 큰 동그라미 4개로 보여 줍니다. 가로 화면 시안도 있습니다. | `b-stand-light.html/.png`, `b-stand-light-landscape.html/.png` |
| C 카운트다운형 | 검은 바탕에 흰 글자와 강조색 하나만 씁니다. 바뀌기까지 남은 박 수를 아주 크게 보여 주고, 아래에 마디 진행 칸을 둡니다. | `c-countdown-black.html/.png` |
